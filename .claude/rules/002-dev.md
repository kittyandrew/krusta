# Development

## Gates

Run these before presenting work as done. Heavy commands run one at a time under a memory cap: the desktop has
been OOM-killed by uncapped parallel builds.

```bash
cap() { systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0 "$@"; }
nix develop .#lint -c tests/lint.sh  # every formatter, linter and type checker, as CI runs them
tests/suite.sh                       # every flake check, VMs side by side; `tests/suite.sh vm-kitter` runs one
cap nix build .#extension            # the unpacked add-on; .#xpi is the same files zipped
sites/kitter/tests/budgets/run.sh    # kitter's speed budgets (docs/design.md), alone on a quiet machine
```

CI (`.github/workflows/quality.yml`) runs `tests/lint.sh` alone, nothing that compiles, so a new gate goes in that
script; `tests/suite.sh` runs it too. A check that keeps its run as `.run` (`tests/judge.nix`) is a VM check to
`tests/suite.sh` with no edit there. Runs are serial across the machine: the suite shares kubicle's
`/tmp/kubicle-suite.lock` and waits on it. Its evidence goes to `$XDG_RUNTIME_DIR/krusta-suite`; a
`KRUSTA_SUITE_DIR` of your own must be yours alone (the suite checks) and short, as the VMs' sockets live in it.

Flakes see only files in git's index: `git add` a new file before any `nix` command, or it does not exist.

## Tests

- **No unit tests**, as in kubicle: every suite runs the real extension in a real Firefox against a fake site
  serving recorded answers, fetched by hash and never committed. Each suite is its own flake check.
- **Only checks that can fail stay.** When adding one, plant the bug it guards against and show it fails.
- **vm-kitter** runs kitter in Firefox Developer Edition against a fake X in a VM (`sites/kitter/tests/fixture/`),
  with recorded answers fetched by hash. `nix build .#checks.x86_64-linux.vm-kitter.plants` runs every planted bug,
  in six VMs at once. A plant is a `substituteInPlace` in `sites/kitter/tests/vm.nix`; a new scenario gets one
  there. The shell's own scenarios (takeover, `?krusta=off`, the toolbar button) run there too.
- **A failed VM check is read, not rerun:** `nix build .#checks.x86_64-linux.vm-kitter.run --print-out-paths`
  holds the journal (Firefox's console), `fake-x.log`, Firefox's network log, and a screenshot and HTML per
  failure; a plant part's is at `.plants.parts.p0.run` and so on.
- **The live feed needs a signed-in site**, which only Andrew's browser has: a Zen of krusta's own with a copy
  of his cookies checks it, and runs `sites/kitter/tests/bench/run.sh` after a change that could move the bench
  (`004-zen.md`).

## Style

- Rust: `rustfmt.toml` (141 columns), clippy pedantic as set in the workspace `Cargo.toml`. rustfmt only
  reflows, so write under line pressure: a body as one statement where that reads as plainly, which
  `fn_single_line` keeps on one line; a repeated phrase as a one-line helper (`items`); no branch that only
  differs in one value. rustfmt leaves `view!` markup alone: lay it out by hand to the same 141 columns.
  Nix: alejandra; TOML: taplo; JS, JSON, CSS: prettier. Prose comments wrap at about 110 columns.
- Imports: one `use` per root, deeper paths inside its braces (`use wasm_bindgen::{JsCast, prelude::*};`),
  never an inner `{...}` group, which rustfmt always breaks over lines.
- Parse once, at the boundary: a site's API crate turns its JSON into types, and its client takes those types as
  they are, never re-reading or re-checking the site's fields. One type per concept, shared by both crates.
- Generic code is copied per type into the wasm: keep a generic function to the line that needs the type
  (`fetch` around `send`).
- No `unwrap()` or `expect()` on anything from the network or X: return an error. `expect()` is for
  invariants of our own code, with the invariant as its message.
- Comments explain what the code cannot, inline on the line they explain; no tombstones or history. Tag only
  a gotcha `@NOTE:`, a hazard `@WARNING:` or an action `@TODO:`, dated.
- `docs/design.md` changes in the same commit as the behaviour it describes.
